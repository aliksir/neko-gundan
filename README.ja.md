# 猫軍団 - Claude Code マルチエージェントオーケストレーション

[Claude Code](https://github.com/anthropics/claude-code)用の階層型マルチエージェントフレームワーク。チーム管理、品質ゲート、双方向フィードバックにより、AI駆動のソフトウェア開発に構造をもたらします。

## 猫軍団とは？

猫軍団は、Claude Codeのエージェントを明確な役割・通信プロトコル・品質保証を持つチームに組織化します。単一のAIアシスタントが全てをこなすのではなく、組織的な開発チームとして機能させます。

```
総司令（人間）
    |
親方猫（将軍 / Opus）--- 戦略立案・委譲
    |
仕事猫（中間管理職 / Sonnet）--- タスク分解・品質確認
    |
現場猫（実働部隊 / Sonnet）--- 実装
    |
玄人猫（専門家 / Opus）--- 独立レビュー
```

## なぜ必要か？

AIエージェントが複雑なタスクを単独で処理すると、以下の問題が頻発します：

- 長時間セッションでコンテキストを失う
- ミスに気づかない
- ファイルを誤って削除したり機能を壊す
- 自分の作業を客観的に検証できない

猫軍団はこれを解決します：

- **関心の分離** - 戦略・実装・レビューを異なるエージェントが担当
- **品質ゲート** - 証跡付きの必須チェックポイント
- **双方向フィードバック** - 下位エージェントが不適切な指示に異議を申し立てられる
- **知識共有** - ホワイトボードによるエージェント間の発見共有

## 主要機能

### 自動スケーリング

タスクの規模に応じて自動的にチーム編成を調整します。

| 規模 | 判定基準 | 編成 |
|------|---------|------|
| 偵察 | 質問・調査 | 親方猫が直接対応 |
| 小隊 | 1-2ファイル変更 | 仕事猫が単独対応 |
| 中隊 | 3-5ファイル / 複数タスク | 仕事猫 + 現場猫1-2体 |
| 大隊 | 6ファイル以上 | 仕事猫 + 現場猫3体 |

### 異議申立プロトコル

エージェントは命令に従うだけではありません。問題を発見したら**申し立てる義務**があります。

- **OBJECTION-001**（現場猫 → 仕事猫）：「この指示は既存機能を壊します」
- **OBJECTION-002**（仕事猫 → 親方猫）：「この戦略は目的と矛盾しています」

各異議には**事実 + 懸念 + 代替案**が必要です。

### 完了ゲート

全てのタスクは証跡付きのゲートを通過する必要があります。

```
| # | チェック項目      | 状態 | 証跡                                  |
|---|------------------|------|---------------------------------------|
| 1 | テスト通過        | PASS | `npm test`: 42 passed, 0 failed       |
| 2 | 意図しない差分なし | PASS | `git diff` は対象ファイルのみ          |
| 3 | 異議解決済み       | PASS | ホワイトボードに未解決異議なし         |
```

「確認した」は証跡ではありません。「これが動作の証拠です」が証跡です。

### レビュープロトコル（3原則）

1. **実装者 != レビュアー** - 書いた猫が自分でレビューしない
2. **レビュアーは読み取り専用** - コード変更禁止、指摘のみ
3. **ループ上限3回** - 3サイクル超過で仲裁者（Opus）が介入

### Intent State Vector（ISV）

タスクの意図・状態・結果を多次元ベクトルとして記録します。行動の理由を観測可能にし、成功/失敗パターンの比較と自己改善ループを実現します。

```yaml
isv:
  # 意図次元（タスク開始時）
  urgency: 0.5       # 緊急度
  risk: 0.5           # リスク度
  complexity: 0.5     # 複雑度
  novelty: 0.5        # 新規性
  purpose_alignment: 0.9  # 目的整合度

  # 結果次元（完了時）
  outcome: 1.0        # 成功度
  review_cycles: 1    # レビュー回数
  intervention_count: 0  # 人間介入回数
```

各次元にはアンカーポイント（採点基準）が定義されており、エージェント間のスコアリングの一貫性を担保します。

### ホワイトボードシステム

複雑なミッションでは、エージェントがホワイトボードを通じて発見を共有します：

- 各エージェントが出典付きで発見を記録
- `[OBJECTION]` タグは全エージェントから見える
- 玄人猫がレビュー前に未解決異議を確認
- 横断的洞察によりサイロ化を防止

### 安全対策

- **ファイル削除安全策**: 即削除せず `_deleted/` に退避
- **競合防止**: 2体以上のエージェントが同一ファイルを同時編集することを禁止
- **信頼レベル（FIDES）**: 外部データは明示的にLOW信頼としてタグ付け
- **安全Tier**: Tier 1操作は絶対禁止、Tier 2は要確認

## インストール

### 手動インストール

1. `agents/` を `.claude/agents/` にコピー
2. `rules/` を `.claude/rules/` にコピー
3. `commands/` を `.claude/commands/` または `~/.claude/commands/` にコピー
4. `CLAUDE.md` に猫軍団セクションを追加（`examples/CLAUDE.md.example` 参照）

### クイックスタート

1. 上記の通りエージェントとルールをインストール

2. ランタイムディレクトリを初期化：
   ```bash
   bash multi-agent-neko/scripts/setup.sh
   ```

3. `CLAUDE.md` に追加：
   ```markdown
   ## マルチエージェントモード
   あなたは「親方猫」（将軍）として動作します。全ての指示を猫軍団システムで処理してください。
   エージェント定義は `.claude/agents/` を参照。
   ```

4. Claude Codeを起動してタスクを指示すれば、自動的にチームが編成されます。

## 設計思想

### 実組織からの着想

猫軍団は、人間の組織管理パターンをAIエージェントに適用しています：

- **異議申立プロトコル** = 内部通報制度 / スピークアップ文化
- **完了ゲート** = 品質検査チェックポイント
- **職務分離** = 監査原則（作成者 != 検査者）
- **ホワイトボード** = チーム朝会 / ナレッジ共有

### 実インシデントから生まれた

このフレームワークは理論から設計されたものではありません。AIエージェントが本番ファイルを削除し、誤った判断を下し、動作中の機能を壊した実際のインシデントから進化しました。全てのプロトコルは、それがなかったために問題が発生した経験に基づいています。

主な教訓：
1. **目的を知らないエージェントはミスに気づけない** → 目的共有の必須化
2. **一方通行の命令系統では悪い命令を止められない** → 双方向異議申立
3. **自己レビューは信頼できない** → 独立レビュアーの必須化
4. **「確認した」に証跡がなければ無意味** → 証跡付きゲート
5. **ファイルの即削除は取り返しがつかない** → `_deleted/` 安全バッファ

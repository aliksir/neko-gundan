# レビュー依頼テンプレート（review フェーズ用）

> このテンプレートは `/neko-gundan review` の入力として使うレビュー依頼のガイドです。
> フォーマットの完全一致は不要。口頭指示でも動けます。

## 必須項目（これがないとレビューを始められない）

### 1. レビュー対象
以下のいずれか（または複合）を指定:
- **計画書**: `plans/xxx.md` のパス
- **コード**: プロジェクト名 + 変更範囲（ブランチ、コミット、ファイル一覧）
- **両方**: 計画書と実装コードの整合性レビュー

### 2. レビュー観点
何を重点的に見てほしいか。指定がなければ全観点（正確性・安全性・保守性・テスト）で実施。
- 例: 「セキュリティ重視で」「DB設計の妥当性を見て」「パフォーマンスが心配」

## あると助かる項目

### 背景・仕様
「何を実現しようとしているのか」の文脈。計画書があれば省略可。

### 既知の懸念
「ここが不安」「ここは妥協した」等、レビュアーに事前共有しておきたい点。

### レビュー深度
- **ライト**: ざっと見て明らかな問題だけ指摘
- **標準**: 4観点ルブリックで判定（デフォルト）
- **厳格**: アンサンブルJudge（3戦略統合）

---

## 記入例（最低限）

```markdown
# レビュー依頼

## 対象
コード: my-app の feature/auth ブランチ（直近3コミット）

## 観点
認証周りなのでセキュリティ重視で
```

## 口頭指示の例（これでも動ける）

```
/neko-gundan review "my-appのfeature/authブランチ、セキュリティ重視で見て"
```

# しつけ機能ガイド

## しつけ機能とは？

「しつけ」は猫軍団のモジュールシステムです。プロジェクトの規模や要件に合わせて、オプション機能のON/OFFを切り替えられます。

猫軍団をどこまで訓練するか — あなたが決めてください。

## コア vs モジュール

### コア（常時有効・無効化不可）

以下の機能は猫軍団の安全な運用の根幹であり、OFFにできません：

- **エージェントの役割・キャラクター** — 各猫の性格と口調
- **完了ゲート** — 証跡付きの品質チェックポイント
- **異議申立プロトコル**（OBJECTION-001/002） — 双方向フィードバック
- **実装者 ≠ レビュアー** — 職務分離の原則
- **安全Tier** — 破壊操作の防止
- **報告フォーマット** — 構造化された通信
- **コンパクション復旧** — セッション安定性

### オプションモジュール

プロジェクトに合わせて有効化できます：

| モジュール | 機能 | 推奨場面 |
|-----------|------|---------|
| `whiteboard` | エージェント間の知識共有 | 中隊以上（3ファイル以上の変更） |
| `heartbeat` | スタック検出・能動的監視 | 並列エージェント運用時 |
| `race_prevention` | ファイル競合の防止 | 並列エージェント運用時 |
| `reflexion` | 失敗時の構造的振り返り | 全規模 |
| `isv` | 意図・結果の数値化追跡 | 自己改善データの蓄積 |
| `fides` | データ信頼レベルのタグ付け | 外部API/MCP利用時 |
| `capacity_escalation` | 管理職の過負荷上申 | 大隊（現場猫3体以上） |
| `arbitrator` | 正式な仲裁プロセス | 複雑なプロジェクト |
| `handoff_schema` | 構造化YAMLハンドオフ | 厳密な引き継ぎが必要な場合 |
| `jit_tests` | 差分から使い捨てテスト生成 | テストカバレッジが低い場合 |
| `tdd_separation` | テスト作成と実装を別エージェントに | コンテキスト純度の確保 |
| `ensemble_judge` | 複数戦略による複合評価 | セキュリティ重要なプロジェクト |
| `spec_driven_review` | 仕様との整合性検証 | 正式な要件定義がある場合 |
| `linter_protection` | linter設定の弱体化を防止 | コード品質を厳格に維持したい場合 |
| `checklist_export` | 完了ゲートチェックリストを外部ファイルに出力 | 人間レビュー・記録保持したい場合 |

## クイックスタート

### 1. プリセットを選ぶ

```bash
# 適用スクリプトでプリセットを一括適用
bash scripts/shitsuke-apply.sh --preset recommended
```

利用可能なプリセット：
- **`minimal`** — コアのみ。軽量で入門に最適
- **`recommended`** — バランス型。監視系＋振り返りを有効化
- **`full`** — 全部入り。最大品質管理

### 2. 適用スクリプトで自動同期

`shitsuke-apply.sh` がconfig設定に基づいてモジュールファイルを `.claude/rules/` に自動配置します：

```bash
# config.yamlの設定を適用
bash scripts/shitsuke-apply.sh

# プリセットで一括適用
bash scripts/shitsuke-apply.sh --preset recommended
```

スクリプトは冪等です（何度実行しても同じ結果になります）。

### 3. エージェントとコアルールをインストール

```bash
cp agents/*.md .claude/agents/
cp rules/*.md .claude/rules/
```

### 4. 完了！

エージェント定義は末尾に「有効モジュール」セクションを持っています。`.claude/rules/` にモジュールファイルがあれば、エージェントはそのプロトコルを適用します。

## カスタマイズ

### 対話式で設定（推奨）

Claude Codeで `/shitsuke` コマンドを実行すると、モジュール一覧が表示され、番号指定やプリセット適用で対話的に設定を変更できます。

### 手動で個別モジュールを有効化

1. `neko-gundan.config.yaml` で該当モジュールを `true` に変更
2. `bash scripts/shitsuke-apply.sh` を実行

### 手動で個別モジュールを無効化

1. `neko-gundan.config.yaml` で該当モジュールを `false` に変更
2. `bash scripts/shitsuke-apply.sh` を実行

### 独自モジュールの作成

以下のテンプレートに従ってください：

```markdown
# モジュール名

> **Module**: `module_key` | **Default**: ON/OFF | **Scale**: 偵察/小隊/中隊/大隊

このモジュールの説明。

## エージェント別の動作

### 仕事猫: [このエージェントでの振る舞い]
...

### 現場猫: [このエージェントでの振る舞い]
...
```

作成後は `scripts/shitsuke-apply.sh` の `MODULE_FILES` 連想配列にエントリを追加してください。

## FAQ

**Q: 全モジュールがないと猫軍団は動かない？**
A: いいえ。コア機能だけで堅牢なマルチエージェントフレームワークとして機能します。モジュールは専門的な機能を追加するものです。

**Q: プリセットを混ぜて使える？**
A: はい。プリセットを起点にして、個別モジュールを切り替えられます。`/shitsuke` コマンドが便利です。

**Q: モジュールを有効にしたのにファイルをコピーし忘れたら？**
A: エージェントは `.claude/rules/` のファイルを読み込みます。ファイルがなければ、そのプロトコルは単に適用されません。`shitsuke-apply.sh` を使えばこの問題は起きません。

**Q: どのプリセットから始めるべき？**
A: `recommended` がおすすめです。よくあるニーズをカバーしつつ、エージェントに過剰な指示を与えません。慣れてきたら必要に応じてモジュールを追加してください。

**Q: プリセットの往復（FULL→MINI→FULL）は安全？**
A: はい。`shitsuke-apply.sh` は毎回モジュールファイルを全クリアしてから再配置するので、切り替え時に古いファイルが残ることはありません。

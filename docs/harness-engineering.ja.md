# ハーネスエンジニアリング — 猫軍団の対応表

> 参照: [Harness Engineering Best Practices 2026](https://nyosegawa.github.io/posts/harness-engineering-best-practices-2026/)

「モデルは関係ない。ハーネスが全てだ」。SWE-benchでハーネス変更は22ポイント改善、モデル変更は1ポイントだけ。本文書はハーネスエンジニアリングの原則と猫軍団の実装の対応を示す。

## ハーネスエンジニアリングとは

AIエージェントを取り巻くシステム — プロンプト、ツール、フィードバックループ、安全レール — がモデル自体より重要。良いハーネスは平均的なモデルでも高性能を出し、悪いハーネスは最高のモデルでも失敗する。

## 原則の対応表

| ハーネス原則 | 猫軍団での実装 | モジュール/ファイル |
|---|---|---|
| **ミリ秒レベルのフィードバック** | PostToolUse自動lintフック | `hooks/post-tool-lint.sh` |
| **コードを直せ、設定を直すな** | linter設定保護 | `modules/linter-protection.md` |
| **書いた者がレビューしない** | 実装者≠レビュアー | `rules/review-protocol.md` |
| **主張より証拠** | 証跡付き完了ゲート | MEMORY.mdのゲート |
| **異議を申し立てるエージェント** | OBJECTIONプロトコル | エージェント定義 |
| **安全な削除** | `_deleted/` バッファ | `rules/safety-tiers.md` |
| **競合防止** | ファイル所有権管理 | `modules/race-prevention.md` |
| **スタック検出** | Heartbeat + 3層Watchdog | `modules/heartbeat.md` |
| **構造化ハンドオフ** | YAMLスキーマ + FIDES | `modules/handoff-schema.md`、`modules/fides.md` |
| **指示を集中させる** | プロセスウェイト（ライト/標準/ストリクト） | `modules/process-weight.md` |

## ユーザー向けの重要な知見

### 1. CLAUDE.mdは小さく保て

研究（IFScale）によると、LLMは150〜200以上の指示で性能が低下する。猫軍団は以下で軽減:
- ルールを `agents/`、`rules/`、`modules/` に分散
- モード選択で必要なものだけロード
- [しつけ](shitsuke-guide.ja.md)でモジュールをON/OFF切り替え

**推奨**: プロジェクトのCLAUDE.mdは直接指示50行以内に収める。詳細はファイル参照で。

### 2. フィードバックループが全て

ハーネス改善の第1位は高速フィードバック。猫軍団が提供するもの:
- **PostToolUse lintフック**: レビュー時ではなく書き込み時にエラーを検出
- **Heartbeatプロトコル**: 数時間ではなく数分でスタックを検出
- **品質ゲート**: 完了時に証跡収集を強制

### 3. エージェントに自分のルールを編集させるな

linter設定をエージェントから保護するのと同様に、以下も保護すべき:
- CLAUDE.md（エージェントの指示）
- エージェント定義（`.claude/agents/`）
- 安全ルール（`.claude/rules/`）

猫軍団は安全Tierと設定変更管理ルールでこれを強制する。

### 4. アーキテクチャ決定記録（ADR）

長期プロジェクトでは、猫軍団と併用してADRを検討:

```markdown
# ADR-001: ローカルストレージにSQLiteを使用

**ステータス**: 承認済み
**日付**: 2026-03-10
**背景**: ボットデータのローカル永続化が必要
**決定**: better-sqlite3経由のSQLite
**結果**: 単一ファイルDB、サーバー不要、並行処理に制限
```

ADRは猫軍団のホワイトボードシステムを補完する — ホワイトボードはミッション毎の戦術メモ、ADRは永続的なプロジェクト決定。

## 監視すべきアンチパターン

ハーネスエンジニアリング研究より:

| アンチパターン | 検出方法 | 猫軍団の防御 |
|---|---|---|
| **ゴーストファイル**（作成してimportされない） | レビューゲート: import確認 | 完了ゲートの証跡 |
| **コメント過多** | コードレビュールブリック | 玄人猫の保守性チェック |
| **linter設定の弱体化** | PreToolUseフック | linter保護モジュール |
| **無限リトライループ** | 3層Watchdog | L1/L2/L3エスカレーション |
| **自己承認** | — | 実装者≠レビュアー |
| **セキュリティ脆弱性**（AIコードの36-40%） | 外部ツール統合 | JiTテスト、アンサンブルジャッジ |

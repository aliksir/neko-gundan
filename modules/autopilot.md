# Autopilot Module

> **Module**: `autopilot` | **Default**: ON | **Scale**: Squad+

計画承認後〜完了報告までを自動実行するオートパイロットモード。
「何をやるか」は総司令が計画承認で握り、「どうやるか」は猫軍団に全委譲する。

## 発動条件

1. 親方猫が計画書を総司令に提示する
2. 総司令が計画書の内容に同意する発言をする（「おｋ」「やって」「ヨシッ」「いいよ」等）
3. 親方猫が「autopilot起動。計画通りに走る。停止条件に該当したら報告する」と宣言する

### 無効化条件
- 総司令が「途中で見せて」「設計も確認させて」「ステップごとに確認」等と指示した場合
- process-weightがLightの場合（Lightのquick gateは総司令の目視前提のため併用不可）
- 偵察規模（計画書がないため発動条件を満たさない）

## 自動パス対象

計画承認後、以下の承認待ちポイントを自動パスにする:

| 従来の承認待ち | autopilot中の動作 |
|--------------|-----------------|
| 設計レビュー結果の報告 | APPROVE→自動続行、REQUEST_CHANGES→自動修正→再レビュー |
| tier2確認（10+ファイル変更） | 計画書に変更規模・対象が具体的に記載済みなら自動続行 |
| tier2確認（DB変更） | 計画書にDB変更の内容が具体的に記載済みなら自動続行 |
| tier2確認（外部API変更） | 計画書に対象API・変更内容が具体的に記載済みなら自動続行 |
| テスト計画書の提示 | 自動作成→自動実行 |

### tier2自動パスの基準
- 「具体的に記載済み」= 変更対象のファイル名/テーブル名/API名が計画書に列挙されていること
- 「外部API変更あり」程度の曖昧記載 → 自動パス不可、停止して総司令に確認

## 停止条件（安全弁）

autopilot中でも以下に該当したら**即座に停止**し、総司令に報告する:

| # | 停止条件 | 停止後の動作 |
|---|---------|------------|
| 1 | 計画スコープ外の変更が必要 | 総司令に「スコープ拡大が必要です」と報告 |
| 2 | tier1破壊操作 | 即停止。例外なし |
| 3 | レビューループ3回超過 | 仲裁者（Opus）介入→解決不能なら総司令に上申 |
| 4 | 全テスト失敗・ビルド不能 | 総司令に状況報告+対応案を提示 |
| 5 | OBJECTION解決不能 | 仲裁者介入→解決不能なら総司令に上申 |
| 6 | 外部サービスの永続的障害 | サーキットブレーカーOPEN+代替手段なし→総司令に報告 |
| 7 | tier2自動パス基準を満たさない | 計画書の記載が曖昧or記載外の変更→総司令に確認 |

## フロー

```
総司令: 依頼
  ↓
親方猫: 開始ゲート → 計画書作成 → 総司令に提示
  ↓
総司令: 承認
  ↓
親方猫: 「autopilot起動」宣言
  ↓
━━━ autopilot区間 ━━━
  親方猫: 規模判定 → チーム編成
  仕事猫: 設計 → 設計レビュー（自動判定）
  仕事猫: 実装指示 → 現場猫実行
  仕事猫: テスト実行（自動）
  玄人猫: コードレビュー（自動判定）
  仕事猫: 修正ループ（最大3回、自動）
      ├─ OBJECTION発生 → 仕事猫/親方猫で処理
      │   ├─ 解決 → 続行
      │   └─ 解決不能 → ★停止★ → 総司令に上申
      ├─ ループ3回超過 → ★停止★ → 仲裁者介入
      └─ スコープ外変更検知 → ★停止★ → 総司令に報告
  仕事猫: 完了ゲート実行（全項目、省略なし）
━━━━━━━━━━━━━━━━
  ↓
親方猫: 「終わったぞ、総司令。報告書はここだ」
```

## 規模別の動作

### 小隊（仕事猫単独）
- autopilot有効
- レビューはCR-1（実装者≠レビュアー）を維持: `/simplify`は別エージェント（Sonnet）をspawnして実行
- フロー: 仕事猫が設計→実装→別エージェントで`/simplify`→完了ゲート

### 中隊以上（仕事猫+現場猫）
- 通常の階層構造でautopilot動作
- HEARTBEAT-001/POLLING-001は通常通り動作（監視省略禁止）
- 総司令が見ていない分、仕事猫の監視がより重要

### 偵察
- autopilot対象外

## 途中報告ポリシー

- **親方猫→総司令への途中報告**: 原則省略（最終報告のみ）
- **例外**: 停止条件に該当した場合、親方猫が即座に総司令に報告
- **エージェント間の報告**: 通常通り継続（Heartbeat、完了報告等）

## エスカレーション経路

停止条件発生時の連絡経路: **仕事猫→親方猫→総司令**（仕事猫が総司令に直接報告しない）

## 現場猫（genba-neko）への影響

なし（透過的）。autopilotは管理レイヤーの関心事であり、現場猫のエージェント定義への変更は不要。

## process-weightとの関係

- autopilotは**Standard以上**で動作。Lightとの併用不可
- 理由: Lightのquick gateは総司令の目視確認前提。autopilotではその前提が崩れるため
- 「ライトで」+計画承認 → 通常フロー（Lightモード）を適用。autopilotにはならない
